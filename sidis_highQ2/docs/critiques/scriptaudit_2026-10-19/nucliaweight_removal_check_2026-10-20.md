## 2. NucliaWeight mechanics

- **Semantics**: H1NuclIACor::GetWeight (H1PhysUtils; A. Meyer wrapper, Fortran ani_ineff_ by K. Daum) — per-reco-track, **MC-only multiplicative down-weight NW = 1 - loss in (0,1]** correcting nuclear inelastic interactions in detector material "undescribed by MC", bringing over-efficient MC track efficiency down to data. Species dispatch: pion hypothesis (ipart=1) default for every reco track; after gen-match refined to kaon (ipart=2) if |PDG|=321; **proton -> 1.0 exactly** (no proton path); unmatched keep pion default; -1.0 sentinel on non-finite. Depends on (species, charge, pt, phi, theta, dca, z0=PVz, run number queried inside the event loop).
- **Application point**: computed and **stored at tree-fill time** by the v6 builder H1ChargedSidis_HighQ2/src/ChargedSidisTreeBuilderHighQ2_v6.C — declaration L652, branch booking L707 (chargedTree->Branch("NucliaWeight",...)), pion default/sentinel L1639-1650, kaon/proton refinement L1830-1840, combined-track loop L1985-1994. **Applied downstream, not at fill**: the stage-2 response builder cone_s2prime_optA_2026-10-19/build_migration_th2_per_charge_cone_s2prime_optA.py L1374-1381 reads the branch, maps non-finite->1.0, clips to [0, NUCLIA_CLIP=10.0] (L597), and forms w_reco = w1*w2*wn on **body AND fake reco legs**; pool/miss/prior gen legs use w1*w2 (CTG has no NW branch, structurally); C_rad gen-only trees have none; fitnorm templates exclude it by convention.
- **Sides**: **MC only.** On data the builder's isMC gate skips the call and the framework would return 1.0 with a "Do not apply to data" warning anyway — data-tree NucliaWeight == 1.0 identically. No data-side NW exists to remove.
- **Range**: pooled selected-track means dj 0.989723 / rg 0.989486 (per-ReqID 0.9893-0.9898; ~95.7% < 1); single-file RAD means 0.9845-0.9846 both generators; one-file median 0.9914 / mean 0.9864; min can be negative (-2.583 anomaly, ~4e-6; downstream clip at 0; QA clipped-low counts dj 115 / rg 98 of 77.0M/64.5M selected tracks); max 1.0; protons exactly 1.0 (6996/6996 audited); inclusive pi+/pi- both 0.9867; charge-differential residual -1.4e-5.

- **Stored vs baked — STORED, not baked**: NucliaWeight is its own per-track float branch on ChargedTot; it is **never folded into weight1/weight2** (single-site HAT event-level reads; weight2 == 1.0 on all audited samples; exhaustive assignment grep in the reference section 12.9). It is baked only into *derived* artifacts (merged migration/response histograms, S2' category exports), all re-derivable from the trees. **Removal therefore needs no tree re-production.**

## 3. Minimal removal-test route

**(a) Stored-branch route (the actual case).** Host: a copy of build_migration_th2_per_charge_cone_s2prime_optA.py with wn forced to np.ones(n) at the single site L1374-1381 (the code already contains this as its NW-branch-absent fallback; no existing CLI flag covers it — argparse has only --mc-root-files/--mc-label/--out-root/--n-files/--dump-*/--smoke-*). A +/-X*(1-NW) transform (wn' = 1 -/+ X*(1-wn)) at the same site yields the model-variation form at identical cost. It is **neither** the tracking_eff_m0p5 data-side-drop construction (impossible: data NW == 1.0, nothing to drop) **nor** a shifted-DV detector leg (those shift data vector + response, cone_s2prime_shiftedlegs_2026-10-14, 7 DVs x 2 gens); it is closest to the shifted-leg *machinery* (per-leg merged response -> stage-2 re-unfold -> delta vs nominal, the budget19 STEP-6 DET_NPZ/DET_DV pattern) with the variation **MC-response-side only**, same species as the DJ-diagnostic legs. Stages to re-run: (1) per-file response rebuild on Condor (OPT-A scale: rg 58,768,556 + dj 69,695,815 checked matched rows; RG31-only suffices for the central leg); (2) merge (merge_migration_per_charge_cone_s2prime_optA.py); (3) stage-2 re-unfold (run_bgsub_setrprime_reunfold_cone_optA.py, IBU k=4, nominal data_sub', nominal bgsub) -> sigma_varied per 490 rows; (4) delta vs nominal. **Not needed**: tree re-production, C_rad (gen-only, NW-free), data vector, R' fitnorm (NW excluded there anyway), lumi/trigger. Scope decision: minimal leg = response-only (A, eps, prior go NW-off coherently since prior = body+miss); a fully coherent variant would additionally re-derive the S2' f_i/category exports (fake legs carry NW too) — the same Condor pass can emit both.
**(b) Baked route: moot.** Had it been baked, the scope would have been a full central tree re-production (865 MC files + data) behind a v6 builder flag — explicitly not required.
**(c) Where it should live.** First as a **diagnostic** in the OPT-A study tree (output_v6/studies/optA_response_rebuild_2026-10-19/, beside stage2_setrprime_optA_2026-10-19/ and straddle_fullsample/, or a new studies/nuclia_off_sensitivity_<date>/), with a docs record and an upgrade of the register entry "NucliaWeight r_min proxy" from BOUNDED_CAVEAT_OPEN to measured. As a budget component it requires supervisor sign-off in the regeneration window: the C1-fix driver is complete through STEP 27 (smoke output budget_env100_optA_c1fix_2026-10-20_smoke/ exists; full run pending) and has **no NW slot** — adding one means re-opening the driver (new STEP + CSV column + re-derivation record + the L215-222 asserts). It would interact with the detint review's recommended material-validity bound ((+) NW 1-r_min ~ 1.8%) and with bgsub_fakefrac_rel, which already carries the NW-suspected r_min scale.
**(d) Physics caveat on interpretation.** Because NW is MC-only, the test varies only the MC response/efficiency — "removing it from data" is vacuous. A flat removal measures **the magnitude of the applied correction on the final cross-section — not the material-model uncertainty**: the expected effect is already bounded by three independent artifacts at **O(0.45%)** integrated (NWeff counterfactual -0.4502%/-0.4515%; ~0.45% body-vs-pool marginal deficit; raw-yield +0.9-1.0 pp on a >=11% deficit), shape-dependent (largest in low-acceptance / low-pT / forward bins where 1-NW is largest). The defensible *systematic* for material-model validity is instead a variation of the correction itself (+/-50% of (1-NW), the H1-style parameter variation the vanished source_NucliaWeight.json was awaiting adjudication on, vs its +/-100% envelope) — same builder site, same cost. And since NW is charge-symmetric to 1.4e-5, the NW-off delta nearly cancels in h-/h+ asymmetries; it is a cross-section/multiplicity-scale statement.
